# River Harpoon

A small, data-driven harpoon game for low-vision research. The player stands on the shore, aims a large high-contrast ring at floating objects and presses one button to spear one of them. Everything that varies between trials is set in Godot Resources (`.tres`).

```
river/
  scripts/           gameplay (rules, spawner, harpoon, logger, ...)
  scripts/input/     AimInput + XR and PC/Mac implementations
  scripts/skin/      RiverSkin, Scenery, SkinModel (visual-only layer)
  data/              demo objects, pools, tasks, rewards, session
  data/experiments/  complete experiments (character_match)
  skins/lagoon/      the lagoon look: scenery, water/sand shaders, model wrappers
  art/               downloaded CC0 models + sky (see art/CREDITS.md)
  tools/             reference_image_maker (renders PNGs of objects)
```

## Playing on PC, Mac or VR
Press **F5**. The input is picked automatically:

| Where | Aim | Fire |
|---|---|---|
| VR headset (Quest, SteamVR) | right controller (`XRAimRight`, aim pose) | trigger |
| PC / Mac | mouse, **or** arrow keys / WASD, **or** gamepad left stick | left click, Space, Enter, gamepad A |

Remap the PC/Mac keys in **Project Settings > Input Map** (`harpoon_fire`, `harpoon_aim_*`). If those actions are missing, default bindings are added at runtime.

To support another device, write a script that `extends AimInput`, implement `get_aim_ray()` and emit `confirm_pressed`, then assign the node to **RiverGame > Input > Input Override**.

## Data (gameplay)

| Resource | What it holds |
|---|---|
| `RiverObjectConfig` | id, tags, visual (placeholder shape/colour **or** `scene`), `size`, `movement_speed` (m/s, 0 = stationary), `rotation_speed` (deg/s), `rotation_axis`, `initial_rotation_degrees`, `float_height` |
| `SpawnPool` | id, list of object configs, `count`, `unique` |
| `RiverTask` | **Presentation**: `text`, `reference_image`, `reference_object` + `show_reference_model`. **Answer**: `rule`, `pools`. **Trial**: `fixed_seed`, `retry_until_correct`, `time_limit` |
| `RewardTable` | `RewardEntry` list: object id and/or pool id → item + quantity |
| `RiverSession` | task list (a task may appear several times), reward table, `fixed_seed`, `shuffle_tasks`, feedback texts and timings |

Choose which session runs on the **RiverGame** node (`session`).

## Looks (visual only): stimuli vs. decoration
- A **stimulus** (what the participant must judge) sets its model on the object config (`scene`). An example is the characters in `data/experiments/character_match/objects/`.
- **Decoration** lives in a `RiverSkin` (`skins/lagoon/lagoon_skin.tres`): the scenery, per-object model overrides (`object_scenes`, keyed by object id) and the spear model. Assign it on **RiverGame > Skin**. Clear it to get the plain high-contrast placeholder version back. `hide_with_scenery` lists the template nodes (floor, table, ...) that are hidden while the scenery is shown.
- Models are always scaled to the config's `size` and centred. To turn a model or loop its animation, wrap it in a scene whose root uses `SkinModel` (see `skins/lagoon/models/*.tscn`). The spear model has its tip at the origin and points −Z.
- `Scenery` copies its `environment` (sky, fog, colour grading) onto the world environment while it is loaded, and restores the original when removed.
- Logs record which visual each object actually showed (`visual`).

## Rules
`StandardRule.kind`: `FASTEST_ROTATION`, `SLOWEST_ROTATION`, `FASTEST_MOVEMENT`, `SLOWEST_MOVEMENT`, `SAME_AS_REFERENCE` (config id equals `reference_object`, or the task's reference_object if that is empty), `FROM_POOL` (`pool_id`). Speeds are compared by absolute value. Ties within `tie_tolerance` all count as correct.

**Custom rule:** make a script that `extends TaskRule` and overrides `find_targets(objects, task) -> Array[RiverObject]`, then choose it in a task's `rule` slot. `tag_rule.gd` is a 15-line example.

## Example experiment: find the character from a 2D image
`data/experiments/character_match/` runs 10 trials. Five characters stand still and spin at 400°/s. The task panel shows a 2D picture of one of them, and the player must spear that character.
- `objects/*.tres`: one config per character (`scene` = the model, `rotation_speed` = 400, `movement_speed` = 0).
- `characters_pool.tres`: all 5, `count` = 5.
- `tasks/find_*.tres`: `reference_image` = the PNG, `reference_object` = the target, rule `SAME_AS_REFERENCE`.
- `character_match_session.tres`: each task listed twice (10 trials), `shuffle_tasks` on.
- `images/*.png`: generated by `tools/reference_image_maker.tscn`. Open it, set the folders in the Inspector, and press **F6**.

## Harpoon (fixed input conditions)
- Selection is geometric and deterministic. The picked object is the one whose pick sphere is at the smallest angle from the aim ray, as long as that angle is within `assist_angle`. There is no physics, spread or recoil.
- On confirm the target is chosen and `fired` is emitted first. The spear animation plays after that and never changes the result.

## Logs
Logs are written to `user://trial_logs/session_<time>.jsonl` (full detail) and `.csv` (one row per trial). On Windows that is `%APPDATA%\Godot\app_userdata\<project>\trial_logs`; on macOS it is `~/Library/Application Support/Godot/app_userdata/<project>/trial_logs`.

Each trial records its seed, every spawned object (config values, visual, start position), the correct targets, each selection (time, correctness, aim ray), misses, the response time, the outcome and the rewards. To replay a run, set the session's `fixed_seed` to the logged `session_seed`.

## Exporting for PC / Mac
Use **Project > Export**. The **Windows Desktop** and **macOS** presets are included; install the export templates when Godot asks. The Mobile renderer runs on Direct3D 12 or Vulkan on Windows and on Metal on macOS. OpenXR is skipped automatically when there is no headset.
